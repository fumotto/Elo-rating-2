**環境変数（概要）**

- フロントエンド（Vite）
  - ファイル: `.env.example` (ルート)
  - 主な変数:
    - `VITE_SUPABASE_URL` — Supabase プロジェクトの URL（例: https://your-project.supabase.co）
    - `VITE_SUPABASE_PUBLISHABLE_KEY` — publishable key（クライアントで使用）
    - `VITE_APP_ENV` — `development` / `production` など
  - 使用方法: ルートの `.env.example` をコピーして `.env.local` / `.env` に必要値を設定して利用します。
  - 旧来の `VITE_SUPABASE_ANON_KEY` も一部互換性のため読み込まれますが、最新構成では `VITE_SUPABASE_PUBLISHABLE_KEY` を優先してください。

- Supabase（セルフホスト／スタック）
  - フォルダ: `supabase-project/.env.example`
  - 主な変数:
    - `SUPABASE_URL` — Supabase API の URL
    - `SUPABASE_PUBLISHABLE_KEY` — publishable key
    - `SUPABASE_SECRET_KEY` — secret key（サーバー側のみで取り扱う）
    - `SUPABASE_JWKS_URL` — JWKS の URL
  - 多数のシークレットと設定が含まれます（`SUPABASE_SECRET_KEY` などの機密は絶対にクライアントに公開しないでください）。
  - `setup.sh` や `run.sh` で `.env.example` を `.env` にコピーして利用するフローが用意されています。

**セキュリティ・ベストプラクティス**

- 秘密鍵や service_role 相当のキー（`SUPABASE_SECRET_KEY`, `SERVICE_ROLE_KEY` など）はリポジトリやフロントエンドコードに決して含めない。
- リポジトリには `.env.example` のみを含め、実際の `.env` は `.gitignore` で無視すること（このリポジトリは `!.env.example` を用いて例ファイルを含めています）。
- GitHub Actions では `Repository secrets` を使用してデプロイ用のキーを安全に渡す。
- ローカルで複数プロジェクト（dev/prod）を扱う場合、接頭辞 `VITE_SUPABASE_URL_DEV` 等を用いて環境別に管理するか、`.env.development` / `.env.production` を使う。

**運用メモ**

- OAuth リダイレクト URL は Supabase の Auth 設定で登録する必要があります（README の手順参照）。
- `supabase-project/.env.example` はセルフホスト環境向けに非常に多くの設定を含むため、変更前にバックアップを取ること。
- 追加した環境変数をプロジェクトドキュメントや CI セットアップに追記してください（`README.md` の `Repository Secrets` セクションは既に主要な変数を列挙しています）。
